# Rozwiązywanie problemów

[English](TROUBLESHOOTING.md) | **Polski**

| Objaw | Co sprawdzić |
|---|---|
| `WARNING: no reply from receiver` w logu nadajnika | IP komputera, zapora Windows (UDP 5005), czy `key` jest taki sam po obu stronach |
| Wysoki ping / skoki w oknie receivera | Wi-Fi na nadajniku (najlepiej kabel Ethernet - przy telefonie przez hub USB; potem `nmcli radio wifi off`); nadajnik bez roota - log `Low latency: ... run with doas` (procesor nadajnika usypia się głęboko) |
| Duże „Bluetooth (ponad minimum)” na karcie pada (kilka ms i więcej) | wbudowane radio nadajnika kolejkuje raporty (np. telefon: ~10 ms, dongle USB: ~1 ms). Wepnij dongle Bluetooth USB - nadajnik sam go wybierze i wyłączy wbudowane (panel Bluetooth → Kontroler: Auto albo „Użyj” przy donglu; log `Bluetooth adapter (auto): hciN ... (USB)`), potem sparuj pady z donglem. Dongle Realtek (np. TP-Link UB500) potrzebuje firmware: Alpine / postmarketOS `apk add linux-firmware-rtl_bt`, Debian / Raspberry Pi OS `apt install firmware-realtek`, Arch `pacman -S linux-firmware-realtek` (starsze: `linux-firmware`) - bez niego w `dmesg` jest `RTL: firmware file ... not found`. Sprawdź też odległość i przeszkody między padem a nadajnikiem |
| Panel Bluetooth: pady zniknęły po wpięciu / wyjęciu dongla | każdy kontroler ma własny adres - sparuj pady z tym, którego nadajnik używa (panel: kontroler oznaczony „używany”). Nie chcesz zmian: „Użyj” przy wbudowanym albo Ręcznie (`bt_adapter` w `sender.toml`) |
| Gyro kręci w złą stronę | edytor → Gyro aim → „Invert horizontal / vertical” |
| Celownik / kamera powoli „płynie” sama | widok Test → wykres gyro przy leżącym padzie; jeśli nie jest płaski - „Kalibruj żyroskop” |
| Postać idzie sama / kamera się kręci (gałka) | widok Test → „Zmierz dryf” → „Zastosuj” (korekcja dryfu tego pada) |
| Nie da się dociągnąć gałki do końca (nakładka, słaba ręka) | widok Test → Dostępność → „Dostosuj do ręki” albo suwak zasięgu ręcznie |
| Ruch odwrócony w emulatorze (DSU) | `acc_sign` / `gyro_sign` w konfiguracji receivera |
| Emulator na innym urządzeniu nie widzi serwera DSU | od przeglądu bezpieczeństwa słucha tylko na tym komputerze: `dsu_bind = "0.0.0.0"` w `receiver.toml` |
| Pady nie działają po powrocie do starszej wersji (z `key`) | usuń `auth.json` obok nowszej strony (tam zapamiętany jest protokół v3) |
| Profil gry się nie włącza | gry z anti-cheatem mogą blokować odczyt nazwy procesu; przełącz ręcznie PS + d-pad |
| `virtual pad error ... ViGEmBus` | zainstaluj sterownik ViGEmBus albo HIDMaestro (README) |
| Ustawienia → Pady: „HIDMaestro nieużywany” | „not found” = HIDMaestro jeszcze się nie pobrał (Ustawienia → Pady → „Sprawdź teraz”; błąd pobierania jest pod nim) albo zła własna ścieżka; „administrator rights required” = odmowa w oknie UAC przy starcie - „Uruchom ponownie jako administrator” (autostart podnosi uprawnienia sam, dziennik: „Autostart ustawiony na uprawnienia administratora”); „pythonnet not installed” = `pip install pythonnet`; „.NET 10 runtime not installed” = przycisk „Zainstaluj .NET 10” (winget) albo ręcznie .NET 10 Runtime; „cannot load its types: …” = brak pliku obok `HIDMaestro.Core.dll` (nazwa w komunikacie) - przy własnej ścieżce DLL skopiuj go z zipa HIDMaestro albo zostaw pustą ścieżkę (pobranie automatyczne); inny błąd przy tworzeniu = ten pad przez ViGEmBus, szczegóły w dzienniku |
| Dziennik: `tworzenie pada: HMResourceInUseException ...` / `HMDriverVersionException ...` (HIDMaestro 2.0) | komunikat wskazuje przyczynę: inny program (albo drugi receiver) zajmuje indeks lub tożsamość pada - zamknij go; niezgodny albo brakujący sterownik - uruchom receiver ponownie (pierwszy start po aktualizacji HIDMaestro instaluje sterownik od nowa, kilka sekund). Każdy program zbudowany jeszcze na HIDMaestro 1.x usuwa przy starcie wszystkie urządzenia HIDMaestro w systemie (także z 2.0) - wszystkie programy na komputerze muszą być na 2.0. Gdy profil zostanie odrzucony, „HIDMaestro has no 'dualsense' profile (refused: plik: ścieżka JSON: powód)” podaje powód. Ten pad idzie przez ViGEmBus do czasu naprawy |
| Okno UAC przy każdym uruchomieniu | zadanie `DualSenseBridgeAdmin` tworzy receiver działający jako administrator - zatwierdź UAC raz; konto bez uprawnień administratora zawsze pyta (albo `--no-elevate` i ViGEmBus) |
| Pad 2 jest graczem 1 | Ustawienia → Pady → „Stała kolejność graczy” włączona; który fizyczny pad jest padem 1, pamięta nadajnik (`sender/slots.json` - usuń wpis, żeby przydzielił slot od nowa) |
| Pad nie wibruje | karta pada: „stary nadajnik” = zaktualizuj nadajnik (Aktualizuj w oknie), „brak uprawnień” = nadajnik nie działa jako root (`sudo` / `doas` albo usługa z `install-service.sh`), „brak w jądrze” = jądro nadajnika bez `CONFIG_PLAYSTATION_FF` i `CONFIG_HIDRAW`, „nie znaleziono pada” = brak `/dev/hidraw` tego pada; na nadajniku: `sudo python3 sender_rumble.py --test` (wibruje każdym sposobem po kolei, bez sieci) i ustaw w `sender.toml` `rumble` na ten, który działa; log nadajnika `rumble via ...` i `rumble N/N from PC` (czy polecenie z PC dochodzi); przycisk „Wibracja” na karcie pada |
| Wake-on-LAN nie budzi komputera | czerwony błysk = nadajnik nie zna MAC (Ustawienia → Wake-on-LAN: wpisz go albo uruchom raz komputer z działającym nadajnikiem); biały błysk, a PC śpi = WoL wyłączony w BIOS / sterowniku karty, karta Wi-Fi albo „Szybkie uruchamianie” Windows (wyłącz je przy WoL z pełnego wyłączenia); log nadajnika `Wake-on-LAN ... -> ...` |
| Tryb konsoli włącza się dopiero po ~minucie od startu PC | dziennik: „Receiver uruchomiony N s po starcie Windows” - duże N = stary autostart z wpisu Run (Windows go opóźnia); receiver sam przenosi go do Harmonogramu zadań (wpis w dzienniku), ręcznie: `python receiver_controller.py --autostart on`. „Tryb konsoli czeka - na pierwszym planie X” = program X spoza listy w Ustawieniach → Tryb konsoli |
| Tryb konsoli nie reaguje | log receivera: `Console: double ... on controller N` = wykryte; `only the master pad can do that` = funkcja zastrzeżona dla mastera (Ustawienia → Master) |
| Panel Bluetooth: szara kropka / „brak danych” | nadajnik offline albo starszy niż v10 - Aktualizuj |
| Panel Bluetooth: czerwona kropka | opis w podpowiedzi: „brak uprawnień” = nadajnik nie działa jako root, „usługa bluetooth nie działa” = `sudo systemctl enable --now bluetooth`, „brak busctl” = system bez systemd, „zablokowany (rfkill)” = `sudo rfkill unblock bluetooth` |
| Sparuj: „parowanie odrzucone” / „brak odpowiedzi urządzenia” | pad nie jest w trybie parowania (Create + PS, aż lightbar szybko miga) - włącz go i uruchom skanowanie jeszcze raz; pad sparowany wcześniej z konsolą: Zapomnij, potem Sparuj |
| Pad sparowany, ale nie ma go jako P2, a włączony przyciskiem PS mruga kilka sekund i gaśnie | BlueZ nie zapisał klucza (adapter bez `Pairable`) albo pad nie był zaufany. Nadajnik ustawia teraz zaufanie sam; pad bez klucza jest zapominany - włącz go w trybie parowania (Create + PS), uruchom skanowanie i Sparuj jeszcze raz |
| Gra w co-op widzi pady dziwnie (Steam) | Steam → biblioteka → gra → Właściwości → Kontroler: spróbuj „Wyłącz Steam Input” (gra czyta dwa DS4 sama) albo odwrotnie; kolejność graczy w Big Picture → Ustawienia → Kontroler |
